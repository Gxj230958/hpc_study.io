# HPCG：稀疏计算与通信的另一面

HPCG 使用预条件共轭梯度相关计算来评估系统。相比 HPL，它包含更多稀疏访存、向量操作和通信，帮助观察另一类应用特征。

## 稀疏矩阵有什么不同

稀疏矩阵只存储部分非零元素，还要保存它们的位置。计算时除了读数值，还要读索引，访问可能不连续。因此 GPU 或 CPU 的浮点峰值很高，也不保证这类任务很快。

HPCG 的计算包括稀疏矩阵向量乘、归约和预条件处理。增加进程后，邻域交换与全局通信会影响时间。它不是“比较慢的 HPL”，而是不同的负载。

## 小规模运行

使用 [HPCG 官方源码](https://github.com/hpcg-benchmark/hpcg)。编译时选择与本机 MPI、OpenMP 一致的配置。`hpcg.dat` 指定局部网格和目标运行时长。

```text
HPCG benchmark input file
Small educational run
16 16 16
1
```

这是一秒目标时长的教学配置，程序实际耗时还包括准备与验证。具体合法尺寸由所用版本约束。运行后读取生成的报告，检查验证项，保留配置和源码版本。

```bash
mpiexec -n 1 ./xhpcg
```

短跑不符合正式提交的完整时长要求，不能以此宣称获得正式 HPCG 成绩。正式规则以对应版本官方说明为准。

## 与 HPL 一起理解

若 HPL 表现较好、HPCG 较低，可以提出“访存或通信可能限制性能”的假设。但两项分数本身不能定位具体瓶颈，仍需分析工具与控制变量实验。

练习：局部网格三条边都翻倍，局部点数如何变化？

??? success "参考答案"
    点数变成八倍。边界面积大致变为四倍，因此体积与边界通信的比例也会改变。真实通信还受分区方式影响。

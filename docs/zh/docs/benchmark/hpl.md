# HPL：稠密线性方程的计算能力

HPL 求解稠密线性方程组 `Ax=b`，使用双精度计算和分布式内存并行。它适合观察稠密数值计算能力，不代表所有应用的速度。

## 计算量与内存量

矩阵边长为 N 时，主要存储约为 `8*N*N` 字节，实际还需工作区与其他开销。主计算量约为 `2/3*N^3` 次浮点运算。增大 N 会很快提高计算成本，不要一开始填满内存。

HPL 通常依赖高效 BLAS 和 MPI。BLAS 的矩阵乘法性能对结果影响很大。使用通用、未优化 BLAS 的结果不能直接代表硬件潜力。

## 先认识 HPL.dat

| 参数 | 含义 | 起步建议 |
| --- | --- | --- |
| N | 矩阵边长 | 先用 256 或 512 检查流程 |
| NB | 分块大小 | 先固定为 64 |
| P、Q | 进程网格 | P×Q 等于 MPI 进程数 |

取得 [HPL 官方源码](https://www.netlib.org/benchmark/hpl/)，按随包 `INSTALL` 配置 MPI 与 BLAS。完成编译后，在包含 HPL.dat 的目录运行：

```bash
mpiexec -n 1 ./xhpl
```

本仓库还提供 `scripts/run-reference-benchmarks.sh`，在 Linux 上构建小规模参考版本。完整流程见[实验索引](../learning/labs.md)。

## 怎样读输出

检查求解结果的残差验证是否通过，再读取时间和 GFLOP/s。N 太小会受初始化、通信和调度影响。小规模通过只证明运行流程和该规模正确性，不是 TOP500 正式成绩。

调参时固定 MPI 进程数、BLAS 线程数和输入；不要无意形成多层线程过度订阅。保留实际 HPL.dat 与原始输出。

练习：N 翻倍，矩阵存储与主计算量大致变为多少？

??? success "参考答案"
    存储约四倍，主计算量约八倍。实际时间还受并行效率和访存影响，不一定刚好八倍。

参考：[HPL 算法与文档](https://www.netlib.org/benchmark/hpl/)。

# 通信成本：测延迟，也测消息大小

通信有启动成本，也有按数据量增长的成本。本节学习一个简单模型，并实际运行 ping-pong 实验。

## 延迟加传输时间

简化模型为 `T(n) ≈ α + n / B`。α 是启动延迟，n 是字节数，B 是有效带宽。它适合建立直觉，不包含拥塞、协议切换、拷贝和同步的全部细节。

两个 rank 轮流发送同一块数据，rank 0 测量完整往返时间。往返除以二可以作为对称路径下的单程估计，但不能当作精确的单程观测。

## 运行实验

```bash
mpiexec -n 2 python examples/mpi/pingpong.py
```

程序分别测试 1 字节、1 KiB、1 MiB。先预热十轮，再计时一百轮。输出是平均每轮的往返微秒数。计时有噪声，应多次运行，报告中位数及范围。

本机启动的两个进程可能通过共享内存通信。这个实验可以学习消息大小的影响，不能作为跨机器网络成绩。集群实验需要记录节点、进程放置和互连类型。

## 优化时问三个问题

能否减少通信次数？能否减少字节数？能否在等待通信时做不依赖结果的计算？三者都有代价，例如批量合并增加延迟，压缩增加计算和数值误差。

练习：1 字节消息耗时 4 微秒，1 MiB 消息耗时 100 微秒，能否说带宽增加了？

??? success "参考答案"
    不能。小消息主要受固定开销影响，按字节除时间得到的有效速率很低。要比较带宽，使用足够大的消息，并明确单程或往返统计口径。

参考：[OSU Micro-Benchmarks](https://mvapich.cse.ohio-state.edu/benchmarks/)。

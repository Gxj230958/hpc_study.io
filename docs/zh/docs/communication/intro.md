# 通信：把局部工作连成整体

把数组分给多个进程之后，各进程只知道自己的数据。要得到最终答案，它们必须交换信息。本节用求和认识通信，前置知识是[进程](../thread-process/process.md)。

## 先问需要交换什么

假设两个进程各处理一半数组。每个进程可以先算出一个部分和，最后只交换两个数，不必把整个数组反复传输。选择算法时，先寻找可以在本地完成的工作。

另一类任务需要邻居数据。例如一维温度模拟中，一个网格点的新温度依赖左右相邻点。把网格分块后，边界进程要交换边缘数据。这些额外边缘数据常称为 halo。

```mermaid
flowchart LR
    A[rank 0 的网格] <-->|边界数据| B[rank 1 的网格]
    B <-->|边界数据| C[rank 2 的网格]
```

## 点对点与集合通信

点对点通信描述发送方与接收方。集合通信描述一个通信器中所有成员共同执行的操作。广播把一份数据分发出去；归约把多个值按求和、最大值等规则合并。

集合通信不是“随便哪个进程调用都行”。参与者需要遵守匹配顺序。也不要假设所有集合调用都等同于 barrier。

## 第一次运行

```bash
mpiexec -n 4 python examples/mpi/sum.py --n 100003
```

查看源码中的 `reduce`：各 rank 提交部分和，rank 0 得到总结果。随后 `bcast` 把验证状态发给所有进程，让它们一致决定成功或失败。

练习：只需要总和时，收集所有原始元素再求和，有什么缺点？

??? success "参考答案"
    通信量和根进程内存都更大。局部求和后归约通常只交换少量数据。但浮点求和顺序可能改变，验证时需要考虑误差。

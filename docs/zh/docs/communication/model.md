# 常见通信模式与完成语义

本节学习如何选择通信操作。先理解[通信导论](intro.md)中的局部结果与全局结果。

| 操作 | 数据怎样流动 | 常见用途 |
| --- | --- | --- |
| Broadcast | 一个进程到所有进程 | 分发参数 |
| Scatter | 根进程把不同分块发出去 | 分发输入 |
| Gather | 各进程把分块交给根进程 | 汇总输出 |
| Reduce | 多份数据合并到根进程 | 全局误差、求和 |
| Allreduce | 合并后每个进程都有结果 | 梯度同步 |
| Alltoall | 每个进程分别发给其他进程 | 数据重排 |

## 阻塞不等于对方已经处理完

阻塞发送返回，通常表示发送缓冲区可以安全重用，不表示对方已经完成计算。小消息有时被内部缓冲暂存，大消息则可能等待接收方配合。不要根据某次小规模运行推断所有规模都不会死锁。

非阻塞通信返回请求对象。程序必须调用 `Wait` 或 `Test` 等操作确认完成，然后才能安全重用相关缓冲区。

```python
request = comm.Isend(array, dest=peer, tag=0)
do_work_that_does_not_touch_array()
request.Wait()
```

这是 API 顺序示意。`array`、`peer` 和计算函数需由应用提供。仅使用非阻塞 API，并不能保证计算与传输实际重叠；还取决于 MPI 实现和硬件进展能力。

## 小练习

所有进程都要知道最大的局部误差，应该选择什么操作？先画数据流，再选 API。

??? success "参考答案"
    可以使用 `Allreduce` 和最大值操作。若只让 rank 0 知道，则 `Reduce` 足够。不能把所有操作都替换成广播，因为广播不负责合并多个输入。

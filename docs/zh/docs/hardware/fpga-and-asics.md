# FPGA 与 ASIC：为特定工作设计硬件

CPU、GPU 不是唯一的计算设备。本节只要求理解循环和数据流，目标是知道什么时候需要考虑专用硬件。

## 两种不同的“专用”

FPGA 是可配置的逻辑器件。开发者把运算、存储和连接组织成电路。重新配置后，同一器件可以实现另一种数据通路。它不是“用另一种语言写一个普通 CPU 程序”。

ASIC 是面向特定用途设计的芯片。制造之后，主要电路结构固定。专用矩阵加速器、网络处理芯片都可以属于这个范围。专用设计可能提高能效，但付出开发成本和灵活性的代价。

| 设备 | 常见优势 | 需要付出的代价 |
| --- | --- | --- |
| CPU | 控制逻辑复杂、通用软件丰富 | 大规模规则运算未必最节能 |
| GPU | 大量并行数值运算、成熟库 | 需要足够并行度与数据供应 |
| FPGA | 可定制流水线和数据格式 | 编译时间、资源规划、时序约束 |
| ASIC | 针对目标负载优化 | 电路固定，开发门槛高 |

## 一个流水线例子

任务是对每个输入执行 `y = (x + 1) * 2`。把加法和乘法放到两个阶段后，不同数据可以同时处在不同阶段。第一个结果仍要经过全部阶段，但流水线填满后可以更频繁地产生结果。

假设每阶段一拍、启动间隔一拍，处理 100 个数的理想时间约为 101 拍，而不是 200 拍。这个数字只用于解释流水线；真实设计还有接口、时钟和存储约束。

## 纸面实验与练习

画一张表：列是时钟周期，行是加法和乘法阶段，填入前四个数据的位置。再假设乘法器每两拍才能接收新数据，找出吞吐量的变化。

??? success "参考答案"
    两个阶段都每拍接收数据时，填满后每拍输出一个结果。乘法器启动间隔变为两拍后，长期吞吐量最多为每两拍一个；增加上游缓冲只能吸收短期波动。

不要从峰值运算量直接断定哪种硬件最好。先看数据格式、算子、数据搬运和开发成本。参考：[AMD Vitis HLS 文档](https://docs.amd.com/r/en-US/ug1399-vitis-hls)。

# 互连：数据怎样到达另一块设备

本节把“通信慢”拆成可观察的问题。先读[容量、带宽与延迟](hardware-intro.md)。

## 机器内部与机器之间

CPU 与独立 GPU 常通过 PCIe 连接。多路 CPU 有片间互连。某些 GPU 平台还提供专用的 GPU 互连，但不能假设每张显卡都有。跨节点通信通常经过网卡、交换机和链路。

带宽描述大量数据持续传输的速率。延迟描述启动一次通信和等待响应的开销。小消息往往更在意延迟，大消息更容易暴露带宽限制。

## 先看拓扑

```bash
lspci
nvidia-smi topo -m
```

第二条需要 NVIDIA 驱动。如果只有一张 GPU，输出不能证明多卡互连的性能。`lspci` 缺失时可安装 `pciutils`，也可阅读机器管理员提供的拓扑。

GPU 和网卡是否靠近同一个 NUMA 节点，会影响数据经过的路径。“设备型号一样”不足以保证两台机器的传输速度相同。

## 用模型估算

常用简化模型是 `时间 ≈ 启动延迟 + 消息字节数 / 有效带宽`。例如启动延迟为 5 微秒、有效带宽为 10 GB/s，传 1000 字节的理想估算约为 5.1 微秒。这里的数字是假设值，不是本机测量。

可运行[通信成本实验](../communication/cost.md)改变消息大小。单机 MPI 会使用本地通信机制，结果不能写成“网络带宽”。

练习：把 1000 个小消息合成一个大消息，为什么可能更快？有什么代价？

??? success "参考答案"
    合并减少启动次数。但第一个数据可能要等待其他数据凑齐，增加响应延迟；还可能需要额外缓冲和打包。吞吐量与延迟是不同目标。

参考：[NVIDIA SMI 文档](https://docs.nvidia.com/deploy/nvidia-smi/index.html)、[MPI 标准](https://www.mpi-forum.org/docs/)。

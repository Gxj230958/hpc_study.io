# CPU：核心、指令与向量化

本节帮助你读懂 CPU 参数。学完后，应能解释“频率高”为什么不一定等于“程序快”。需要先了解数组与循环。

## 一条指令不一定处理一个数

CPU 核心执行程序指令。频率表示时钟变化的速度，不直接表示每秒完成的有效工作。缓存命中、分支预测、指令依赖都会影响执行时间。相同频率的两个处理器，也可能有不同表现。

SIMD 表示一条指令对多个数据进行同样的操作。例如一次给多个浮点数加上常量。它适合规则的数组循环。线程并行则把任务分给多个执行线程。两种方法可以同时使用。

逻辑 CPU 不是完整的物理核心。开启 SMT 后，同一物理核心的多个硬件线程会共享部分资源。因此，把线程数翻倍不意味着吞吐量翻倍。

## 从循环开始

```c
for (int i = 0; i < n; ++i)
    c[i] = a[i] + b[i];
```

如果数组之间没有妨碍优化的重叠，编译器可能把这个循环向量化。先让编译器报告结果，再考虑手写指令：

```bash
gcc -O3 -fopt-info-vec-optimized -fopenmp examples/cpu/memory.c -o build/memory-vector
```

先按[环境准备](../learning/setup.md)创建 `build` 目录。报告出现向量化消息，说明某个循环应用了优化；它不是程序整体加速的证明。`-march=native` 可以针对当前 CPU 优化，但生成的程序可能无法在其他机器运行。

## 观察线程数的影响

```bash
make -C examples cpu
OMP_NUM_THREADS=1 ./build/sum 10000000
OMP_NUM_THREADS=4 ./build/sum 10000000
```

两个结果都必须出现 `PASS`。时间会波动。这个求和读取很多内存，最终可能受带宽限制。不能用它单独评价一款 CPU 的全部计算能力。

练习：四线程只比单线程快两倍，是否说明另外两个线程没有工作？

??? success "参考答案"
    不能这样判断。线程创建、内存带宽、调度、串行部分都可能限制加速。先看线程是否运行，再测量程序在哪个阶段等待。

参考：[GCC 优化选项](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html)。下一节：[内存层级](memory.md)。

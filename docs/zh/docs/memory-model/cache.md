# 缓存一致性与伪共享

多个核心有自己的缓存。硬件需要协调同一内存位置的缓存副本。本节学习为什么“写不同变量”有时仍会互相干扰。

## 缓存一致性没有替你加锁

缓存一致性协议协调缓存行的状态，让同一位置的写入按协议传播。它不使 `x++` 自动成为一个原子操作，也不消除 C/C++ 数据竞争。

假设两个线程频繁更新两个相邻计数器。计数器可能恰好位于同一缓存行。线程需要反复取得该行的写权限，尽管从程序角度看它们在写不同变量。这叫伪共享。

```text
同一缓存行：[线程 A 的计数器][线程 B 的计数器][其他数据]
                     写权限可能反复转移
```

## 怎样减少它

先把频繁更新的中间结果放在线程局部变量中，结束时只写回一次。必要时再考虑按缓存行分隔数据。盲目填充会增加内存占用，甚至降低缓存利用率。

OpenMP 的 reduction 正好提供了“局部累加、最后合并”的表达方式。阅读 `examples/cpu/sum.c`，比较它与“每次循环都写共享计数器”的差别。

练习：两个线程只读同一缓存行，是否一定产生伪共享？

??? success "参考答案"
    不会仅因共同读取就产生这种写权限争用。伪共享关注独立数据上的写入干扰。只读共享通常可以有效利用缓存。

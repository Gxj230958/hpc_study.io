# 内存模型：谁能看到哪一次写入

本节建立一个重要区别：硬件提供的缓存机制，与语言规定的程序行为，不是同一层规则。前置知识是[线程](../thread-process/thread.md)。

## 共享地址不代表自动同步

两个线程都能访问一个变量，不意味着它们可以随时同时修改它。编译器可能重新安排指令，处理器也可能以不同顺序完成访存。正确的并行程序必须使用语言或并行库规定的同步方法。

一个常见错误是让线程 A 写数据，再写一个普通布尔标志；线程 B 循环检查标志，然后读取数据。普通变量上的这种访问可能产生数据竞争。标志变了也不是完整的正确性证明。

## 先掌握三个词

**原子性**：一个操作不会被观察成中间完成一半的状态。**可见性**：其他执行单元能否按规定看到写入。**顺序**：哪些操作必须在另一些操作之前发生。

原子操作不总是把其他普通数据一起正确发布。内存序规定了它与其他操作之间的关系。初学者先使用互斥锁、OpenMP barrier 和 reduction 等高层工具。

## 阅读一个安全结构

```c
#pragma omp parallel
{
    #pragma omp single
    initialize_data();
    /* single 末尾默认有隐式 barrier。 */
    use_initialized_data();
}
```

这是结构示意，两个函数需由应用实现。没有 `nowait` 的 `single` 末尾会同步线程。删除同步前，需要证明所有读取仍发生在初始化完成之后。

练习：把所有变量都改成 `volatile` 能解决多线程同步吗？

??? success "参考答案"
    不能。`volatile` 不是互斥锁，也不提供通用的线程间同步关系。使用语言原子类型或并行库同步原语。

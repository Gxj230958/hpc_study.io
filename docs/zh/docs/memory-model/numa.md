# NUMA：内存离哪个 CPU 更近

NUMA 指不同内存位置的访问成本不完全相同。多路服务器中，每个 CPU 插槽往往连接一部分内存。读取另一个节点的内存可能经过额外互连。

## 分配和首次写入

Linux 的内存放置受策略、可用资源和首次触碰等因素影响。常见情况下，首次真正写入页面的线程会影响页面放在哪个 NUMA 节点。仅调用 `malloc` 不一定立即分配全部物理页面。

如果一个线程初始化全部数组，而其他节点的线程随后处理它，数据可能集中在初始化线程附近。对分块并行程序，可以考虑让每个线程初始化自己将使用的区间。

## 看清允许使用的资源

```bash
lscpu
numactl --hardware
numactl --show
```

`numactl` 需要单独安装。容器可能限制内存策略调用或只允许部分 CPU。看见两个 NUMA 节点不代表有权绑定全部节点。

在有权限的独占机器上，可比较：

```bash
numactl --cpunodebind=0 --membind=0 ./build/memory
numactl --cpunodebind=0 --membind=1 ./build/memory
```

只有节点 0、1 存在且被允许时才运行。失败时记录权限或节点限制，不更改共享机器的全局配置。比较需要重复测量，且实验工作集应大于缓存。

## 常见误区

绑定不是越多越好。强制把大程序放入单一节点可能耗尽本地内存。线程数、内存位置和输入分块应一起考虑。

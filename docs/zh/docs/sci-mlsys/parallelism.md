# 并行策略：拆数据，还是拆模型

模型或数据变大后，一张设备可能放不下，也可能算得不够快。本节学习三种基本拆分方式，前置知识是 [MPI 集合通信](../communication/model.md)与训练循环。

## 数据并行

每个工作者保存一份模型，处理不同的数据。计算梯度后进行同步，再更新参数。若希望等价于同一个全局 batch，需要正确处理损失的求和、平均和 batch 大小。

示例：两张卡各处理 32 个样本，全局 batch 通常为 64。若每张卡得到的是局部平均梯度，等量样本时再取平均可得到全局平均。样本数不同则不能简单等权平均。

## 模型并行

张量并行把某些矩阵运算拆到多张卡，例如按输出列切分权重。流水线并行把不同层放到不同设备，数据按阶段经过它们。前者经常需要算子内部通信，后者需要处理中间激活和流水线空闲。

| 策略 | 主要拆什么 | 常见限制 |
| --- | --- | --- |
| 数据并行 | 输入 batch | 每卡仍需模型，梯度需要同步 |
| 张量并行 | 一个算子的张量 | 高频通信，依赖互连 |
| 流水线并行 | 模型层或阶段 | 负载不均和流水线气泡 |

优化器状态和参数分片可以进一步减少重复存储，但会增加通信和执行管理复杂性。

## 单卡也能练习的概念

梯度累积让多个小 batch 的梯度在更新前累加，缓解一次前向的显存需求。它不是多卡并行，也不会自动加速。若要模拟大 batch 的平均损失，需要按实际样本数正确缩放。

完整多卡同步示例见 [NCCL](../gpu/nccl.md)。单卡课程只验证训练与数值流程，不声称验证多卡扩展性。

练习：模型参数已经占满单卡显存，普通数据并行能解决吗？

??? success "参考答案"
    通常不能，因为每张卡仍有完整模型副本。需要考虑模型或状态分片、降低精度、卸载或更小的模型，并计算激活和优化器状态的额外占用。

参考：[PyTorch DistributedDataParallel](https://pytorch.org/docs/stable/generated/torch.nn.parallel.DistributedDataParallel.html)。

# 精度与量化：用更少的位保存数

减少数据位数可以节省空间与传输，但会引入误差。本节区分浮点混合精度与整数表示，先掌握误差，再看速度。

## FP32、FP16 与 BF16

FP16 和 BF16 都用 16 位，但指数与有效数字的分配不同。它们的范围和精度并不相同。混合精度通常让部分计算使用低精度，同时在关键位置使用更高精度累加或保存状态。

```bash
python examples/ml/precision.py
```

程序以 FP64 CPU 结果作为小规模数值参考，比较 CPU FP32、GPU FP32 和 GPU FP16。输入预先放在设备上，使用同步后的主机计时；它不包括输入传输，也不是端到端训练测速。

## 对称 INT8 量化

设最大绝对值为 m，令比例 `s=m/127`。量化时计算 `q=round(x/s)` 并裁剪到 [-127,127]，还原时计算 `x_hat=s*q`。

例如范围约为 [-1,1]，步长约为 1/127。原始 0.5 不能总被精确表示，只能落到附近的网格点。没有裁剪时，理想舍入误差不超过半个步长。

```bash
python examples/ml/quantize.py
```

示例检查误差上界，并比较权重数组字节数。它在 NumPy 中演示量化与反量化，不调用 INT8 矩阵乘法，所以不声称获得 INT8 计算加速。真实模型还需要处理全零张量、异常值和不同张量的尺度。

## 校准与质量

激活范围常需要代表性的校准数据。极端离群值可能让大部分数的量化步长过粗。逐通道尺度可以改善部分情况，但增加元数据与算子要求。

练习：权重文件缩小四倍，推理延迟一定下降四倍吗？

??? success "参考答案"
    不一定。算子支持、反量化开销、访存、batch 大小和其他层都会影响时间。还需验证质量目标是否保持。

参考：[PyTorch AMP](https://pytorch.org/docs/stable/amp.html)、[NVIDIA TensorRT 量化说明](https://docs.nvidia.com/deeplearning/tensorrt/latest/inference-library/work-quantized-types.html)。

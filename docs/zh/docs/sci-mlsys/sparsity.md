# 稀疏性：零很多，是否就能更快

稀疏矩阵包含大量零。我们可以只保存非零项，但还需要告诉程序它们在哪里。本节通过 CSR 和方程求解理解存储与计算的交换。

## CSR 怎么存

CSR 用三组数组保存数值、列下标和每一行的边界。矩阵 `[[2,0,1],[0,3,0]]` 可以表示为：

```text
data    = [2, 1, 3]
indices = [0, 2, 1]
indptr  = [0, 2, 3]
```

第一行读取位置 `[0,2)`，第二行读取 `[2,3)`。索引也占内存，所以只有很少几个零时，稀疏存储未必划算。

## 为什么零不会自动带来加速

普通稠密矩阵乘法通常仍处理整块数据，给权重设零不一定减少计算。稀疏算法需要跳过零，但可能增加索引读取、不规则访存和负载不均。

非结构化稀疏允许任意位置为零。结构化稀疏按块、通道或硬件要求的固定模式删除元素，更容易被特定算子利用，但约束更强。需要同时验证模型质量和实际后端支持。

## 练习

一个 FP32 矩阵有一百万个元素，其中十万个非零。若每项再存一个 32 位列下标，忽略行指针，CSR 约需多少空间？

??? success "参考答案"
    数值和列下标各约 0.4 MB，总共约 0.8 MB；稠密表示约 4 MB。还要加行指针和实际分配开销。省内存不等于一定更快，需要测实际算子。

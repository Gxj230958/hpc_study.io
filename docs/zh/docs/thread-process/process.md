# 进程：独立工作，再交换结果

进程是操作系统管理程序运行的一种方式。本节学习地址空间、进程编号和进程间通信。先读[执行模型导论](intro.md)。

## 同名变量不是同一份数据

两个进程都可以有名为 `total` 的变量。通常它们位于不同的地址空间。一个进程修改自己的 `total`，另一个不会自动看到。要交换数据，需要消息、管道、文件或显式共享内存。

进程有 PID，用于操作系统管理。MPI 中的 rank 是通信器内的编号，范围通常是 0 到进程数减一。rank 不等于 PID，也不表示机器的编号。

## 不需要集群也能练 MPI

按[环境准备](../learning/setup.md)安装依赖后，在仓库根目录执行：

```bash
mpiexec -n 3 python examples/mpi/sum.py --n 10
```

程序启动三个进程。它们分别求和，然后把部分结果归约到 rank 0。只有 rank 0 打印总和，应该得到 45 和 `PASS`。输出中有三个 rank，并不表示用了三台机器。

`mpiexec` 管理这次并行启动。不要在每个 rank 中再次无条件调用 `mpiexec`，否则可能重复启动大量任务。

## 出错时从哪里查

程序挂住时，先看所有进程是否走到了对应的通信调用。某个进程提前异常退出，其他进程可能还在等待。集群上应使用调度器申请资源，再按站点规则启动；不要在登录节点跑大作业。

练习：把 `--n 10` 改为 `--n 2`，仍启动三个进程，会发生什么？

??? success "参考答案"
    有一个进程分到空区间，贡献部分和 0。正确程序仍能得到 1。任务数量不一定能整除进程数，所以空分块应该被允许。

参考：[MPICH 用户文档](https://www.mpich.org/documentation/)、[mpi4py 教程](https://mpi4py.readthedocs.io/en/stable/tutorial.html)。

# 线程：共享数据也需要规则

线程共享所属进程的地址空间，但有各自的执行状态和栈。本节关注共享变量为什么会出错。前置知识是变量读写和循环。

## 一次加法可能包含多步

`counter += 1` 在概念上可以拆成读出、加一、写回。两个线程可能都读到 0，然后都写回 1。虽然执行了两次加一，结果却只有 1。

在 C/C++ 中，未同步地并发读写普通对象可能形成数据竞争，导致未定义行为。不能把“结果偶尔错一个”当作唯一后果，也不能用 `volatile` 修复它。

## 三种常见处理方式

互斥锁让一段代码一次只被一个线程执行。原子操作为特定操作提供不可分割的语义。归约让每个线程先使用局部结果，再统一合并。

求和通常适合归约，而不是给每一次加法都加锁：

```c
unsigned long long total = 0;
#pragma omp parallel for reduction(+:total)
for (int i = 0; i < n; ++i)
    total += i;
```

这是说明关键语法的片段，完整程序见 `examples/cpu/sum.c`。OpenMP 创建工作线程、分配循环，并在末尾合并结果。

## 小实验

运行 `OMP_NUM_THREADS=4 ./build/sum 100003`，记录输出。然后阅读源码，标出只读数组、循环下标、归约变量。先理解谁能写什么，再尝试修改并行代码。

练习：所有线程只读取同一个不再修改的数组，是否需要给每次读取加锁？

??? success "参考答案"
    通常不需要。必须保证数组在读取开始前已正确初始化，且读取期间没有其他线程写它。初始化与发布之间也需要正确的同步关系。

参考：[OpenMP 规范](https://www.openmp.org/specifications/)。继续阅读[内存一致性](../memory-model/consistency.md)。
